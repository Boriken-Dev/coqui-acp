## [Unreleased]

### Added

- `coqui-acp-api`, the crate of coqui-acp's Guatiao kinds: the `acp_harness` kind, so an ACP agent driver can be written in any language Guatiao hosts. `AcpHarness::start(StartRequest, ProcessSpawner, ChannelSink) -> Channel` is one ACP connection over Guatiao's channel kinds, one JSON-RPC message per channel message, its programs started through the host's spawner (`process_spawner` and `spawned_process` object kinds: pipes or a terminal, reads across a dropped link, a kill that ends the tree). `describe`, `refusal` (of requirements held together), `program`, `import_session` and `export_session` are required; `models`, `session_record` and `non_defaults` default to their true empty answers. `StartRequest` carries a secret environment, working roots, requirements with values (`read_only`, `no_commands`, `answer_only`, `no_project_settings`, `no_project_mcp`, `files_under`, `read_only_paths`, `denied_paths`, `network`, `sandboxed_scripts`, `only_skills`), which only narrow. A host seeds a session at a UUID of its own with `import_session` (from a history in the standard format, or empty), which answers an `ImportReport`, then resumes it in ACP; `export_session` gives the history back in pages of whole lines; every session id a harness reports is a UUID. Requests refuse a key they do not declare. `WorkingRoots` is the one comparison of a path with the roots. The kinds ship as data, as JSON Schemas and as a Python module; feature `contract` ships the suite every provider passes, and `acp-harness-check` runs it on a library or a source file. An echo in Rust and one in Python (`examples/provider-python/harness`) pass it.
- `coqui-acp-harness`: feature `kind`, with `LocalSpawner`, the `acp_harness` spawner on this machine, and `ThroughSpawner`, `Spawn` through any host's spawner.
- `coqui-acp-harness`: `Event::Options`, told to the client as a `config_option_update`, so a translator can say its choices changed by themselves; `mode::up_to`, `named` and `custom_option`.
- `coqui_acp_harness::mode`: `Mode` (Manual, Accept edits, Auto, Plan, Bypass) and the `mode` config option every translator offers, so a client shows one control over every harness. `coqui-acp-claude` switches it with `set_permission_mode` and offers Bypass only with `ClaudeLaunch::allow_bypass`; `coqui-acp-codex` switches it at the next turn.

- `coqui_acp` for Dart: `AcpAttachment.link`, a `resource_link` to a resource the agent reads itself, such as a file by its `file:` URI, with its name and optional type and size. Every agent takes one, whatever it advertises, as ACP says, and `isLink` tells it apart.
- `coqui-acp-harness`: `Stream`, reading a harness's output until it ends or it exits with its output held open, with `Settings`-style hooks for each raw line; `line_writer`, so a harness that has stopped reading holds up nobody; `Usage::elsewhere`, `TurnEnd::Stopped { stop, result }` and `PermissionRequest::details`. Working roots and network paths follow links, `max_open_questions`, `max_tool_content_bytes` and `max_tool_content_items` are settings, and `initialize` is answered off the thread that reads the client.
- `coqui-acp-claude`: `permission_prompts`, `SessionStart::Chosen`, and models unknown as distinct from empty. A rejected `rate_limit_event` gives the refused turn it came in its reset time, and `type: error` lines fail the turn. Plugins from a client are off until the host allows them, and held to the working roots.
- `coqui-acp-codex`: `extra_args`, `ClientInfo`, `check_config` and `check_thread`, `steer`, `request`, a question's `details`; a failed `model/list` stops nothing, a turn's end is matched to its id, and a turn given up on touches no later one, whenever it shows itself.
- `tools/record_harnesses`, which records both crates' fixtures from the real tools against a stand-in model; a test compares their arguments with what each launch builds.
- `coqui-acp-harness`: what a translator from a coding agent's own command line to ACP needs, with no Node: `Launch`, `Spawn` and `PlainSpawn`, whose `kill` ends the whole process tree (a job object on Windows, a process group on Unix); `lines`, a harness's output within a line limit, with the last lines that were not protocol; `event`, messages, thoughts, tool calls with diffs, locations and terminals, plans, permission requests with a `Responder`, usage and context, quota, limits, commands, notices, compaction and turn endings; and `acp::serve`, a `Harness` served as an ACP agent in version 1's shapes or version 2's, whichever the client asks for, with `Settings` for sessions (8), requests at once (64), prompt size (16 MiB), line size (64 MiB), the highest version (2), cancel grace (10 s), permission wait (none), tool calls tracked (4096) and events queued for a client that does not read (4096, after which the harness waits), and for what a client may choose: its MCP servers (taken), working roots (any) and network or device paths (refused). `version::untested` warns of a harness version not tested, and refuses nothing.
- `coqui-acp-claude`: Claude Code as an ACP agent over its stream-json protocol, and the command `coqui-acp-claude`. `ClaudeLaunch` (model, effort, appended system prompt, MCP servers, directories, plugin directories, resume, permission mode, setting sources, spending ceiling, each one `--flag=value` argument), `ClaudeSession` (`initialize` with no model turn for models, efforts, commands and version; prompts with images and resources; interrupt; model and effort between turns), `Parser`, history replayed from Claude Code's transcript, and `ClaudeAgent`, with `request_permission` offering Claude Code's own options (allow once, always allow applying its suggested rule, reject) and `_meta.claudeCode.options.plugins` as plugin directories, which a host can refuse with `client_plugins(false)`. MCP servers reach Claude Code through a file only its user can read, never its command line. Tested with Claude Code 2.1.318, against transcripts recorded from it.
- `coqui-acp-codex`: Codex as an ACP agent over `codex app-server`, and the command `coqui-acp-codex`. `CodexLaunch` (model, effort, developer instructions, MCP servers, directories, approval policy, sandbox, `--config` overrides written as TOML), `CodexSession` (models and version with no model turn, prompts with images and resources, `turn/interrupt`, model and effort between turns, a load that replays a thread's turns), `Parser`, and `CodexAgent`, with `request_permission` offering Codex's own decisions for commands, file changes, more permissions and MCP tool calls. A session's `additionalDirectories` are skill roots and writable roots. Tested with Codex 0.164.0 and 0.166.0; another version is a warning.
- `coqui_acp` for Dart: `AcpSessionSetup` on `openSession`, `createSession`, `reopenSession` and `resumeSession`, with MCP servers (`AcpMcpStdio`, `AcpMcpHttp`), an appended `systemPrompt`, `additionalDirectories` and `_meta`, each in the version's own shape. `takesMcp`, `takesSystemPrompt` and `takesAdditionalDirectories` say what the agent advertises, and what it does not is refused before anything is sent.
- `coqui-acp` and `coqui_acp` for Dart: an agent's questions (ACP's `elicitation/create`, form mode) put to the person. `Builder::elicitor` with `Elicitor`, `Elicitation`, `Field`, `FieldKind`, `ChoiceOption` and `ElicitationAnswer`, and `AcpClient`'s `elicitor` with `AcpElicitation`, its `AcpField`s and `AcpElicitationAnswer`, advertise form elicitation only when given one. A question that cannot be put to a person, or an answer that does not fit its form, is answered `cancel` with a `Blocked` event, never an error; another session's is cancelled without asking. `max_elicitation_fields` (64) and `max_elicitation_options` (256), and `maxElicitationFields` and `maxElicitationOptions` in Dart, bound a form. `vectors/elicitation.json` holds both clients to it. URL mode is not offered.
- `coqui_acp` for Dart: a permission request's options reach the decider as `AcpPermissionRequest.options`, each an `AcpPermissionOption` with the agent's id, name and kind, at most `AcpClient.maxPermissionOptions` (16) of them, and `AcpSelect(optionId)` answers with any one of them, `allow_always` and `reject_always` included. An option the request did not offer, or options repeating an id, are answered `cancelled`, with an `AcpBlocked`; `AcpAllow` and `AcpDeny` choose among the options kept. `AcpPermission.optionId` names the option chosen.
- `coqui-acp-bridge`: the Noise method (`coqui-peer-noise`) beside WebCrypto for the in-band proof and PIN pairing. `--method noise|webcrypto` on `keygen`, `serve`, `dial`, `forward`, `pair-accept` and `pair-dial`: an identity keeps the method of its key, naming another is refused, and nothing negotiates or falls back. `serve`, `dial` and `forward` say on standard error which method they prove by. A record and a descriptor `--advertise` publishes name the method.
- `coqui-acp-bridge`: `--key-limit` and `--no-rekey` on `serve`, `dial` and `forward`, each method's own setting with its default. A setting looser than the default is said on standard error. WebCrypto has no key change, so it always ends a session at its limit.

- `coqui-acp`: drive any Agent Client Protocol version 1 agent from blocking code, with permission deciding, resume, extensions and line transports.
- `coqui_acp` for Dart: a client that speaks version 1 and version 2, whichever the agent selects. `openSession`, `setConfigOption`, `setMode` and `AcpCancel` for a client that shows what an agent offers. `listSessions` and `reopenSession` for earlier sessions, and `AcpAttachment` with `takesImages` and `takesFiles` for what goes with a prompt.
- `coqui-acp-bridge`: a stdio ACP agent on the network under coqui-peer identity.
- `coqui-acp-bridge`: `serve --advertise` publishes a DNS-SD record, or a descriptor on loopback; `discover` finds both; `companion install` lets a browser extension ask, over native messaging; `serve --tls-short-lived` lets a browser pin WebTransport with no certificate authority.
- `coqui-acp-bridge`: `serve --paired` and `dial --paired`, on this user's own identity and trust store, so one pairing serves every command. Proof, pairing, discovery and the companion moved to `coqui-agentic-peer`.
- `coqui-acp-bridge`: `serve --service` and `--grant` for several protocols on one link, `grant` for adding one to a paired peer at once, and `dial --fallback` for another endpoint.
- `coqui-acp-bridge`: `serve --forward`, `serve --reverse` and `forward`, for TCP over a link in either direction, each target its own grant.
- `coqui-acp-provider`: `AgentProvider` and `AgentSession`, a Guatiao provider kind for agents in any language Guatiao hosts, pinned at Guatiao `266baf9c`; `AgentEvent` and its string contract (`text`, `tool`, `blocked`, `completed`, `failed`, `cancelled`, `limit`, `denied`); `AcpFacade`, which serves any such provider as an ACP version 1 agent over any transport, with a `Settings` limit for sessions per connection (8), provider calls (`start` 60 s, others 30 s), cancel (10 s), close (10 s), prompt size (8 MiB), output per turn (64 MiB) and per connection (256 MiB), and failed authentication (5), and optional working roots. `coqui-acp` itself does not depend on Guatiao.
- `coqui-acp-bridge`: `mcp-config` and `mcp-shim --peer`, so an MCP client with no ACP session reaches a peer's own tools from one stable entry. A peer keeps a stream of `mcp-offer/1` standing, with the metadata `standing/1`, and each program gets a stream of its own.
- `coqui-acp-page`, and `package:coqui_acp/page.dart` for Dart: a person's agents from a page, over `document.acp`.
- `coqui-acp-bridge`: `serve --linger` keeps a link's agent for a time and gives it back to the same proven peer on a new connection, while the store still accepts that peer, with `--linger-per-peer`, `--linger-total`, `--linger-buffer-bytes` (at most 256 MiB) and `--linger-settle-ms`. Off by default. Output dropped while nobody was connected is said in a `_dev.boriken.coqui.acp/output_lost` notification, first on the next link, and what a kept agent wrote before it ended still goes to its peer. On Unix a helper, `agent-guard`, cleans up a kept agent's process group if the bridge goes; it is cleanup, not containment.
- `coqui-acp` and `coqui_acp` for Dart: `Event::OutputLost` and `AcpOutputLost` report `_dev.boriken.coqui.acp/output_lost`.
- `coqui-acp`: `Builder::ends_turn` says which extension notifications end a turn, so a connection ending after one is no `Event::Failed`, and `Builder::disconnect_detail` says what became of a lost agent, in that event's text. Turns are counted, so a turn sent before the last one's ending arrived is still running when that ending comes.
- `coqui-acp-provider`: `Settings::options`, with `StartOption`, `OptionValue` and `OptionTarget`, for the models, efforts and modes a host lets a client choose. `AcpFacade` answers them in `session/new` and `session/resume` as ACP's `configOptions`, the one of category `mode` also as `modes`, and takes `session/set_config_option` and `session/set_mode` until the provider starts, so `coqui_acp`'s `Builder::model` and `Builder::effort` reach `StartRequest`. A value outside the host's list is refused, there and in the launch `_meta`; a change after the provider started is refused. `Error::Settings` for options that cannot be served.
- `coqui-acp`: `Exchange::describe`, with `Description` and `Answer`, says what an agent offers before any session: its start options as ACP's `SessionConfigOption`s, its modes as `SessionModeState`, and its sessions from `session/list`, each `Known`, `Unknown` with the agent's reason, or `NotSupported` when the agent does not advertise it, in which case nothing is sent. Options and modes come from the `_coqui_acp/session_options` request, sent only to an agent that advertises `dev.boriken.coqui.acp/session_options` in `agentCapabilities._meta` (`SESSION_OPTIONS_METHOD`, `SESSION_OPTIONS_CAPABILITY`). What the agent answers is bounded and kept as data.
- `coqui_acp` for Dart: `AcpClient.describe`, with `AcpDescription` and `AcpKnown`, `AcpUnknown` and `AcpNotSupported`, the same for version 1 and version 2 agents; `vectors/describe.json` holds both clients to one contract. `AcpFailure.code` is the agent's JSON-RPC error code.
- `coqui-acp-provider`: `AcpFacade` advertises and answers `_coqui_acp/session_options` from `Settings::options`, with what the host did not declare as unknown, and `session/list` with the connection's own open sessions.
- `coqui-acp` and `coqui_acp` for Dart: what `describe` keeps is a setting, `Exchange::describe_limits` with `DescribeLimits` and `AcpClient`'s `describeLimits` with `AcpDescribeLimits`, each limit taking any value: options (default 64), values per option (1024), modes (64), sessions (500) and text (4096 UTF-8 bytes). Sessions are listed page by page, following each page's `nextCursor`, up to `pages` requests (10); a later page that fails ends the list with the pages before it. The sessions are a `SessionList` (`AcpSessionList` in Dart) whose `incomplete` says why a list stops short: a later page failed, the sessions limit was reached, or the page limit was. `vectors/describe.json` carries the defaults, and a case may set its own.
- `coqui-acp` and `coqui_acp` for Dart: the size at which agent text is delivered mid-message is a setting, `Builder::text_flush` and `AcpClient`'s `textFlush`, 64 KiB of UTF-8 by default. The Dart client had no such size, so a long message could grow without limit within a turn.
- `coqui-acp`: the tool kinds a session keeps, by which `refuse_kinds` judges a later message about a tool that does not say its kind, are a setting, `Builder::max_tool_kinds`, 4096 tool calls by default and any value taken; before, one was kept for every tool call of the session. At the limit the oldest of a kind not refused is forgotten, which changes no refusal and is said once as an `Event::Notice`. One of a refused kind is never forgotten: a tool of a refused kind that cannot be kept ends the session with `Event::Failed`. The Dart client keeps no such record.

### Changed

- `coqui-acp-harness`: `PlainSpawn`'s kill on Linux and Android also ends the processes that left its group or session, found through `/proc`, and on Unix a watcher in the group ends it when the host ends without a kill.
- `coqui-acp-harness`: the end of an ACP version 2 message carries no `content`, where it carried `[]`, which version 2 reads as clearing the message.
- `coqui_acp` for Dart: under v2, `setConfigOption` sends `type: "id"` beside the value, which v2's `session/set_config_option` requires; a v2 agent holding to the schema refused the request without it. v1's has no type.
- **Breaking** for a provider in Python, `coqui-acp-provider`: Guatiao is pinned at `266baf9c`, and `AgentSession`'s `close` slot is `close` in Python, no longer `close_`, in `python/coqui_acp_provider_kinds.py` as `python -m guatiao.kinds` writes it. The kinds' floor hashes are unchanged. A Guatiao manifest is now `<name>.guatiao`: `examples/provider-python`'s is `echo/acp_echo.guatiao`.
- `coqui-acp-bridge`: the channel crate is `coqui-web-channel`, renamed from coqui-web, pinned at `0b5b05c` (coqui-web's `3b39c00` under its new name, the revision Guatiao's remote source pins), and coqui-agentic-peer at `f6da790`, which pins the same.
- `coqui-acp`: an error's text keeps the agent's reason when `data` is an object with a `message`, as the Grok CLI sends for a spent credit limit, not only when `data` is text.
- `coqui-acp-bridge`: a new identity, from `keygen`, `pair-accept`, `pair-dial`, `dial` or `serve --paired` on a fresh home, proves by Noise unless `--method webcrypto` is given. An identity made before keeps WebCrypto, and its paired peers keep working; moving them to Noise means pairing them again under a Noise identity, which `pair-accept --method noise` makes and records as the home's method.
- `coqui-acp-bridge pair-accept` refuses a browser unless `--origin` lists its origin, so a page cannot spend the PIN; `--run-seconds` (120) bounds one connection, and `--timeout-seconds` defaults to the PIN's own 600 seconds, as does `pair-dial`'s.
- `coqui-acp-bridge`: a home records the method named last, so `serve --paired` naming none keeps working after a home moves to Noise and holds both identities.
- **Breaking**, `coqui-acp` and `coqui_acp` for Dart: stop reason `cancelled` is `Event::Cancelled` and `AcpCancelled`, and no longer `Event::Blocked` and `AcpBlocked`, which now mean only a permission that could not be answered. It ends the turn, so a connection lost after it is no `Failed`.
- `coqui-acp` and `coqui_acp` for Dart: a `session/update` of a session other than the client's own is dropped, and a `session/request_permission` of one is answered cancelled without asking the decider, so what an agent kept from an earlier connection says of its session never feeds this one.
- `coqui_acp` for Dart: request ids start at a random point on each connection, so they do not repeat those of an earlier connection to the same agent.
- `coqui-acp-bridge`: on Windows every agent is in a job object of its own, which the system ends with everything the agent started when the bridge goes, however it goes; stopping an agent ends that job rather than a process tree found by id. On Unix the bridge ends an agent's process group by a system call rather than the `kill` program, and leaves an ended agent uncollected until it is stopped, so its group id cannot be someone else's by then.
- **Breaking**, `coqui_acp` for Dart: the sessions `listSessions` keeps of a page are a setting, `AcpClient`'s `maxListedSessions` (default 500, any value from 0 up), in place of the static constant `AcpClient.maxListedSessions`. Only sessions it can read count toward it, and a page it cuts short says `the sessions limit was reached` in the new `AcpSessionPage.incomplete`, where before the rest of the page was dropped unsaid.
- **Breaking**, `coqui-acp`: the function `exchange` is now `Exchange::new()...run(transport, calls)`, a builder with `client_info`, `authenticate`, `initialize_timeout` and `request_timeout`, so a caller can name itself rather than always being `coqui-acp`. Its waits default to those of `Client::builder`.
