### Added

- `coqui-acp-claude` and `coqui-acp-codex` are `acp_harness` providers (`ClaudeProvider` under the id `claude`, `CodexProvider` under `codex`, each with `ProviderSettings`, a library for a host to load in `examples/` and the account kinds measured on Claude Code 2.1.311 and Codex 0.166.0 in `accounts`). They start the CLI through the host's spawner. `describe` says what they take, that usage is reported (Claude Code only in a turn, Codex readable with no turn) and what they do with the cache hint (Claude Code: `CLAUDE_CODE_PROMPT_CACHE_TTL` and `CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL` to `5m` or `1h`; Codex: ignored). They hold `no_project_mcp` (Claude Code) and `read_only` (Codex) and refuse every other requirement; `models` and `usage` ask the CLI with no turn; they apply the harness's own login only (any other listed account kind is refused until it is applied), and `import_session`, `export_session`, `login` and `renew` are refused `GUATIAO_ERR_UNSUPPORTED` for now. `CodexSession::read_models` lists Codex's models with no thread.
- `coqui-acp-harness`: feature `kind` adds `provider` (`Serving::open` serves a harness over the kind's channel, with the kind's back-pressure and closing rules; `Reports`, what a provider keeps of its connections' usage; catalog helpers), and `Settings::on_usage`.
- `coqui-acp-api` contract suite: `Contract::program_agent` and `acp-harness-check --program-agent` run a provider whose agent is the harness's own program, starting what the provider asks of the suite's spawner for real; the `fake_claude` and `fake_codex` examples are stand-ins for the CLIs that behave as the contract agent does. The suite reads updates by their kind, picks permission options by their `kind`, takes answers in any order and counts a turn unanswered while only updates arrive.
- `coqui-acp-harness`: `serve` answers a line that is no object (a batch, a bare number) and a `method` that is no text `-32600`, as the kind says, where it dropped them.
- `coqui-acp-api`: accounts. The `acp_harness` kind carries several accounts of one harness, chosen per call: `accounts()` (an `AccountCatalog`: the kinds the provider takes, each with a settings schema whose credentials are `writeOnly` and `x-sensitive`, typed endpoints, and whether it rotates, resumes on another account, needs a private directory and renews; the login methods; every credential variable), `login(LoginRequest, spawner, LoginPrompter) -> LoginOutcome` (the provider runs the harness's own sign-in and relays its steps: say, open a URL with a code, ask a form; cancelling or a timeout ends it `GONE` with the tree killed), `renew(RenewRequest, spawner) -> RenewReport` (a renewal with no model turn), and `AccountGrant` (id, kind, settings, `Secret<Credentials>`, directory, revision) on `StartRequest`, `SessionImport`, `SessionExport`, `UsageQuery` and the new `ModelsRequest`. `start`, `import_session`, `export_session`, `models` and `usage` are handed an `AccountKeeper` (object kind `account_keeper`: `renewed`, `lost`; every live keeper of an account hears each event, with a per-account `sequence` the host deduplicates by), and `refusal` takes an `AccountRef`; the new object kind `login_prompter` carries a login's steps. `ProcessSpawner` gains `write_file`, `read_file`, `file_info` and `remove_file` in a private directory the host grants (relative paths only; `..`, absolute paths, streams, device names, links out, pipes and hard links are `NOT_FOUND`; the file bytes are `Secret<SecretBytes>`) and `SpawnerInfo::files`; `PrivateDir` is the one implementation of those rules. A kind break before the first release, with no shim: the hash of `acp_harness` moves from 1326996142 to 4111118208, `process_spawner` from 1466370631 to 4134697914, and `account_keeper` (708146915) and `login_prompter` (2606822037) are new; `StartRequest::account` was the host's opaque text id and is now an `AccountGrant`. `StartRequest::cache_lifetime` (`CacheLifetime`: default, short or long) hints how long the prompt cache should live, and `HarnessInfo::cache_lifetime` says what the harness does with it.
- `coqui-acp-api` contract suite: the accounts checks (the catalog; applying a grant clears every credential variable and leaves a canary credential out of every argument vector, message and reason; an unknown kind, a bad id, a missing credential or directory and a spawner without files refused; a rotated file `renewed` once, a blanked or deleted one `lost` once; `renew`; each login method completing, cancelled and timed out), `Contract::logins` and `Contract::account`, `acp-harness-check --no-logins` and `--account KIND`, and `contract::spawner_files`, which holds a host's spawner to the file methods' rules. - `coqui-acp-api`: usage. One model (`coqui_acp_api::usage`) for how much of each usage allowance an account has used, how it refills and when: a `UsageReport` of `Bucket`s, each with the models it covers (`Coverage`), what it counts (`Unit`: tokens, requests, micro-USD, or permille when only a percentage is known), `used`, `limit` and `remaining`, a `Refill` (a fixed window that resets all at once at `resets_at`, a token bucket that adds `amount` each `per` up to `max`, a balance that never refills) and its own `observed_at`; a `LimitHit` for a refused request, with `resets_at` and `retry_after` as fields; a session's `Spend`. `supported: false` and "nothing reported yet" are different answers. Counts, money and times are integers (Unix seconds, micro-USD) and lengths are Guatiao's `Duration`; a value a newer writer names reads as `Other`. The ACP extension carries it on versions 1 and 2: the capability `dev.boriken.coqui.acp/usage` in `agentCapabilities._meta`, the client's opt-in (`notify`, `account`) in `clientCapabilities._meta`, the request `_coqui_acp/usage` (needs no session and no turn, cheap, so a host may poll it; `-32601` from an agent without it), the notification `_coqui_acp/usage_update` (the whole report on every change) and the limited turn's `_meta["dev.boriken.coqui.acp/limit"]` holding the `LimitHit`. Warning thresholds are the host's. `vectors/usage.json` holds every reader to one spelling.

The contract suite checks both paths (nothing advertised and `-32601` for a harness that reports none; for one that does, polling with no session, revisions that grow on a change and not on a repeat, the notification only for a client that asked, the account, a limited turn ending `refusal` with its `LimitHit`, `usage()` agreeing with the last connection); both echoes take `usage = "none" | "scripted"`.

### Changed

- **Breaking** for a provider of `acp_harness`: the kind gained the `usage` slot, `HarnessInfo` the key `usage` and `StartRequest` the key `account`, so the kind's hash moves (`1326996142`) and every built provider rebuilds. No older shape is read.
- **Breaking** for a provider of `agent_provider`: `AgentEvent::quota`, `usage` and `limit: UsageLimit` are replaced by `report: Option<UsageReport>` and `limit: Option<LimitHit>`; `QuotaReport`, `UsageLimit` and `TokenUsage` are removed.
- **Breaking** for a translator: `coqui_acp_harness::event::{Limit, Quota}` and `Event::Quota` are replaced by `coqui_acp_api::usage::LimitHit` and `Event::Buckets`; a limited turn's `_meta["dev.boriken.coqui.acp/limit"]` is the `LimitHit` (`bucket`, `resets_at`, `retry_after`, `source`, `text`, `observed_at`), no longer `{resetsAt, window, text}`. `coqui-acp-harness` depends on `coqui-acp-api` always; its feature `kind` keeps only the spawners. `coqui-acp-claude` and `coqui-acp-codex` report their windows as buckets, and a Claude usage-limit text names the bucket `seven_day`, no longer `weekly`.
- Guatiao to `0350bae7`: a channel's `close` and `closed` carry a reason, which the `acp_harness` echoes give when they fail, and a Python method that raises gives up what it was handed.
- `coqui-acp-harness`: `PlainSpawn`'s kill on Linux and Android also ends the processes that left its group or session, found through `/proc`, and on Unix a watcher in the group ends it when the host ends without a kill.
- `coqui-acp-harness`: the end of an ACP version 2 message carries no `content`, where it carried `[]`, which version 2 reads as clearing the message.
- `coqui_acp` for Dart: under v2, `setConfigOption` sends `type: "id"` beside the value, which v2's `session/set_config_option` requires; a v2 agent holding to the schema refused the request without it. v1's has no type.
- **Breaking** for a provider in Python, `coqui-acp-provider`: Guatiao is pinned at `266baf9c`, and `AgentSession`'s `close` slot is `close` in Python, no longer `close_`, in `python/coqui_acp_provider_kinds.py` as `python -m guatiao.kinds` writes it. The kinds' floor hashes are unchanged. A Guatiao manifest is now `<name>.guatiao`: `examples/provider-python`'s is `echo/acp_echo.guatiao`.
- `coqui-acp-bridge`: the channel crate is `coqui-web-channel`, renamed from coqui-web, pinned at `0b5b05c` (coqui-web's `3b39c00` under its new name, the revision Guatiao's remote source pins), and coqui-agentic-peer at `f6da790`, which pins the same.
- `coqui-acp`: an error's text keeps the agent's reason when `data` is an object with a `message`, as the Grok CLI sends for a spent credit limit, not only when `data` is text.
- `coqui-acp-bridge`: a new identity, from `keygen`, `pair-accept`, `pair-dial`, `dial` or `serve --paired` on a fresh home, proves by Noise unless `--method webcrypto` is given. An identity made before keeps WebCrypto, and its paired peers keep working; moving them to Noise means pairing them again under a Noise identity, which `pair-accept --method noise` makes and records as the home's method.
- `coqui-acp-bridge pair-accept` refuses a browser unless `--origin` lists its origin, so a page cannot spend the PIN; `--run-seconds` (120) bounds one connection, and `--timeout-seconds` defaults to the PIN's own 600 seconds, as does `pair-dial`'s.
- `coqui-acp-bridge`: a home records the method named last, so `serve --paired` naming none keeps working after a home moves to Noise and holds both identities.
- **Breaking**, `coqui-acp` and `coqui_acp` for Dart: stop reason `cancelled` is `Event::Cancelled` and `AcpCancelled`, and no longer `Event::Blocked` and `AcpBlocked`, which now mean only a permission that could not be answered. It ends the turn, so a connection lost after it is no `Failed`.
- `coqui-acp` and `coqui_acp` for Dart: a `session/update` of a session other than the client's own is dropped, and a `session/request_permission` of one is answered cancelled without asking the decider, so what an agent kept from an earlier connection says of its session never feeds this one.
- `coqui_acp` for Dart: request ids start at a random point on each connection, so they do not repeat those of an earlier connection to the same agent.
- `coqui-acp-bridge`: on Windows every agent is in a job object of its own, which the system ends with everything the agent started when the bridge goes, however it goes; stopping an agent ends that job rather than a process tree found by id. On Unix the bridge ends an agent's process group by a system call rather than the `kill` program, and leaves an ended agent uncollected until it is stopped, so its group id cannot be someone else's by then.
- **Breaking**, `coqui_acp` for Dart: the sessions `listSessions` keeps of a page are a setting, `AcpClient`'s `maxListedSessions` (default 500, any value from 0 up), in place of the static constant `AcpClient.maxListedSessions`. Only sessions it can read count toward it, and a page it cuts short says `the sessions limit was reached` in the new `AcpSessionPage.incomplete`, where before the rest of the page was dropped unsaid.
- **Breaking**, `coqui-acp`: the function `exchange` is now `Exchange::new()...run(transport, calls)`, a builder with `client_info`, `authenticate`, `initialize_timeout` and `request_timeout`, so a caller can name itself rather than always being `coqui-acp`. Its waits default to those of `Client::builder`.
